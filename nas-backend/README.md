# HGhubX NAS 后端

把本地影片目录包装成 HGhubX 能直接接入的服务。零依赖，需要 Node ≥ 18 和 ffmpeg/ffprobe。

    node server.mjs /path/to/media --port 8080 [--cache ./cache] [--cache-max-gb 20]

## 自动分类
- 每个视频文件是一个条目，标题取文件名。
- 顶层文件夹名就是「分类」（客户端分类页动态展示），更深的子文件夹名是额外标签。
- 根目录下散放的视频归入「其他」。
- 封面：与视频同名的 `.jpg/.png/.webp`；没有就用 ffmpeg 截一帧，空闲时后台预生成并缓存。
- 以 `.` 开头的文件（如 AFP 留下的 `._xxx`）会被忽略。

## 客户端设置
「设置 → 接入地址」填 `http://<NAS-IP>:8080`。严格安全模式下，接入地址所在的内网主机会被自动放行。

## 播放与性能
- 首次播放某个视频时用 ffmpeg 封装成 HLS（H.264+AAC 直接拷贝，不重编码；其它编码才转码），缓存在 `cache/hls`，之后秒开。
- 大文件边切边播：切出 3 段就返回，小文件（≤48MB）多等几秒直接给完整可拖动的列表。
- 网络盘带宽是瓶颈：刚被请求、还没开播的视频独占带宽，其余 ffmpeg 暂停（SIGSTOP），开播后再恢复；退出时会清理所有子进程。
- 时长、编码信息持久化到 `cache/probe.json`，重启后不用再读网络盘；空闲时后台预生成时长和封面。
- HLS 缓存超过 `--cache-max-gb`（默认 20GB）后按最近使用时间淘汰。
- 客户端媒体代理不支持 Range，所以必须是 HLS 小分片，不能直接给 mp4。

## 注意
没有账号体系：登录接口接受任意用户名，点赞、收藏、评论只是占位。不要把端口暴露到公网。
