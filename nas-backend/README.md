# HGhubX NAS 后端

把本地影片目录包装成 HGhubX 能直接接入的服务。零依赖，需要 Node ≥ 18 和 ffmpeg/ffprobe。

    node server.mjs /path/to/media --port 8080 [--cache ./cache] [--cache-max-gb 20]

## 随应用启动（推荐）
HGhubX 桌面端内置了对这个后端的托管：「设置 → 本机 NAS 服务」（或首屏的「把本机媒体目录作为片源」）里填好媒体目录并启用后，
应用每次启动都会自动拉起后端、把接入地址指向 `http://127.0.0.1:17680/`，应用退出（包括崩溃）时后端一并退出。
- 启动期间显示启动页：检查环境 → 启动服务 → 扫描媒体库 → 就绪；失败时给出原因（未装 Node / ffmpeg、目录未挂载、端口被占用等）并可重试或改用手动地址。
- 需要本机已装 Node.js ≥ 18 和 ffmpeg（`brew install node ffmpeg`）；后端脚本随应用打包，缓存放在应用数据目录的 `nas-cache`。
- 服务意外退出会自动重启（最多 3 次）；状态变化都会写进 `debug.log`（`[nas] …`）。
- 想单独运行（如放在真正的 NAS 上）则按下面的命令行方式使用。

## 自动分类
- 每个视频文件是一个条目，标题取文件名。
- 顶层文件夹名就是「分类」（客户端分类页动态展示），更深的子文件夹名是额外标签。
- 根目录下散放的视频归入「其他」。
- 封面：与视频同名的 `.jpg/.png/.webp`；没有就用 ffmpeg 截一帧，空闲时后台预生成并缓存。
- 以 `.` 开头的文件（如 AFP 留下的 `._xxx`）会被忽略。

## 客户端设置
「设置 → 接入地址」填 `http://<NAS-IP>:8080`。严格安全模式下，接入地址所在的内网主机会被自动放行。

## 播放与性能
两条播放路径，后端按文件自动选择：
- **直连（mp4/m4v/mov + H.264 + AAC/MP3）**：直接提供原文件，靠 HTTP Range 取流。零等待、不占缓存、快进快退随意跳。客户端本地代理用 1MB 对齐的块缓存（小请求 0 毫秒命中、缺块并发获取、顺序播放预读 8 块、拖动后首块只给 1MB 让画面更早出来），切到下一个视频前会预热它的开头和文件尾。
- **HLS（mkv/avi/HEVC/AC3 等）**：首次播放用 ffmpeg 封装（H.264+AAC 直接拷贝，其它才转码），缓存在 `cache/hls`。大文件边切边播（切出 3 段就返回），小文件（≤48MB）多等几秒直接给完整列表。

通用：
- 网络盘带宽是瓶颈：刚被请求、还没开播的 HLS 任务独占带宽，其余 ffmpeg 暂停（SIGSTOP）；退出时清理所有子进程；客户端中断请求时立刻停止读文件。
- 时长、编码信息持久化到 `cache/probe.json`，重启后不用再读网络盘；空闲时后台预生成时长和封面。
- HLS 缓存超过 `--cache-max-gb`（默认 20GB）后按最近使用时间淘汰。

## 注意
没有账号体系：登录接口接受任意用户名，点赞、收藏、评论只是占位。不要把端口暴露到公网。
